# api/: CLAUDE.md

The **contract** between the apps and the backend (D-020). Future standalone repo: part of `runflow-backend`.

| File | What it is |
|---|---|
| `schema.sql` | PostgreSQL schema: the source of truth for tables and columns, always the full current schema. Every change to it is also a new backend migration (`backend/migrations/NNNN_*.sql`, D-051); a contract test proves the migrations build exactly this. |
| `endpoints.md` | REST catalog: paths, payloads, conventions, workout structure, error format. |
| `mock/seed.mjs` | Deterministic generator for `mock/db.json` (realistic pt-BR data). |
| `mock/db.json` | Seed data: one key per table, rows shaped exactly like `schema.sql`. |
| `mock/server.mjs` | Zero-dependency mock API on `:8787` implementing `endpoints.md`. |
| `starter-library.json` | GENERATED by `mock/seed.mjs`: the workouts every new club starts with, per modality (estimates included). The mock and the backend (synced copy) both read it. |
| `exercise-catalog.json` | GENERATED by `mock/seed.mjs`: Runflow's global exercise catalog (stable ids). The backend upserts its synced copy after migrating. |
| `workout-text-examples.json` | Golden examples for free-text workouts (R1): text + sport → the exact structure, name, warnings and tags. Hand-curated. The mock (`mock/lib/workout-text.mjs`), the web builder (frontend test), the app (its copy of the web file, mobile check) and the backend (synced copy) must all match it. Grammar: `../docs/workout-text.md`. |

## Commands (from the repo root)

- `npm run dev:api` starts the mock. State persists in `api/mock/.data/` (gitignored). Add `-- --reset` to start from the seed again.
- `node api/mock/seed.mjs` regenerates `db.json`.
- `npm run check:api` validates `schema.sql` on real PostgreSQL (PGlite) and smoke-tests the mock, including the workout text examples.
- `node api/mock/workout-text-examples.mjs run "6x1km @4:30 c/ 2' trote"` shows what the free-text grammar understands (any sport instead of `run`).

## Workout text examples (how the founder adds one)

1. Append `{"text": "…", "sport": "run"}` to `examples` in `workout-text-examples.json` (sports: `run`, `swim`, `bike`, `strength`, `mobility`, `other`; an optional `"comment"` says what it should mean).
2. Run `node api/mock/workout-text-examples.mjs --fill`: it writes what the grammar understands today (`name`, `structure`, `warnings`, `tags`) into the new examples. Read the diff.
3. If it's right, commit. If not, fix the expected fields by hand (or leave the text and a `comment` and ask an agent): the checks then fail until the grammar is fixed **in all three ports** (`api/mock/lib/workout-text.mjs`, `frontend/src/domain/quicktext.ts`, `backend/crates/domain/src/workout_text.rs`), the web file is copied to the app (`mobile/src/domain/quicktext.ts`, checked against the same examples by `npm run check -w @runflow/mobile`) and `bash backend/scripts/sync-assets.sh` has copied the file to the backend.

## Rules

- **A schema change is also a migration (D-051).** QA's data is kept: change `schema.sql` and add `backend/migrations/NNNN_name.sql` (`bash backend/scripts/new-migration.sh <name>`) in the same commit; the mock's seed follows `schema.sql` as before.
- **Change the contract before the screen.** A new field or endpoint goes into `schema.sql`, then `endpoints.md`, then `seed.mjs` + `server.mjs`, all in the same commit as the screen that needs it.
- **Mock rows mirror `schema.sql` exactly** (same table and column names). Computed fields in responses (counts, joins) are documented in `endpoints.md`.
- **Dates stay current.** `db.json` has `meta.anchor_date`; on load the server shifts every date and timestamp by (today − anchor), so the demo always looks like "this week".
- **Errors** are problem+json with pt-BR `title`/`detail` and an English `code`.
- Mock-only affordances (fake Google chooser, fake Stripe, fake Strava) live under `/v1/mock/*` or are documented as mock-only. Never rely on them outside dev.
